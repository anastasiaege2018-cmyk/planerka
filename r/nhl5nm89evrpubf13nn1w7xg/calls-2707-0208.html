Почему цифра в отчёте меньше, чем в «Статистике» magent. Это два разных среза, а не ошибка:

1. Разный охват. Отчёт считает встречи только по 120 объектам, на которые за период поступил звонок с ЦИАН. «Статистика» считает встречи по всем 876 объектам агентства — включая те, где клиенты пришли из базы, по рекомендации или с других площадок.
2. Разная привязка к дате. Здесь встреча относится к периоду по дате самой встречи, а при её отсутствии — по дате проставленного результата. «Статистика» использует свою логику и, судя по всему, дату создания записи.
3. Дубли. В отчёте одна встреча = один объект + один клиент + одна дата. Перенос и последующая отмена того же визита считаются одной встречей, а не двумя.
4. Фильтр «Статистики» по датам не применяется при обращении к странице напрямую — она отдаёт значения за месяц по умолчанию. Сверять нужно, выставив период руками в интерфейсе.

Методика. Звонки — ЦИАН public API get-calls-report за 27.07–02.08.2026, только квартиры (офисы и загородная недвижимость исключены из топов). Связь объявления с карточкой CRM — через раздел magent «Звонки ЦИАН API». Встречи — objects/pokazy по каждому объекту; период определён по дате встречи, при её отсутствии — по дате результата. Встречи дедуплицированы по ключу «объект + клиент + дата»: телефон клиента, если он указан, иначе имя. Записи без клиента не схлопываются — их уникальность подтвердить нечем.
Ограничения. CRM теряет часть звонков: ЦИАН отдал 274, в magent записано 245 (−11%). Объект 331455542 (Большая Филевская, 7 звонков, 2-е место по аренде, Валерия Демина) в CRM отсутствует полностью — встречи по нему не подтянулись, в таблицах он помечен прочерком, а не нулём. Колонка «Состоялось» по продаже везде 0 — статусы не заполняются, а не результат равен нулю.
